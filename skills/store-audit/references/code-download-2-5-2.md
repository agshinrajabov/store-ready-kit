# Runtime code download — 2.5.2 risk interview

Guidelines revision: **8 June 2026** · last checked: **2026-10-04** · numbers: 2.5.2, 4.7, and the executable-code section of the
Apple Developer Program License Agreement (DPLA)

## The rule in short

Apps must be self-contained: they may not download, install or run code that adds or changes features after
review. Narrow exceptions exist for educational apps that teach coding (4.7 covers mini apps, games and streaming
in specific forms). The DPLA allows interpreted code (JavaScript and the like) to be downloaded only when it does
not change the app's primary purpose, does not create a storefront for other code, and does not bypass signing,
sandboxing or review of new features.

## Why vibe-coded apps hit this

- App-builder platforms often ship **OTA updaters** by default (Expo Updates, CodePush, Capgo, Shorebird).
- Some generate apps that **render server-defined UI** or run fetched scripts so the builder can "update the app
  instantly".
- Some wrap a **hosted web app** whose features change daily without review.

Apple acted on exactly this pattern in 2026: updates from app-builder platforms were blocked and one builder's
app was pulled entirely. The risk is not the library; it is shipping features that review never saw.

## The interview (ask the developer; record the answers in the report)

1. Does the app download anything executable after install? (JS bundles, scripts, WASM, Lua, plug-ins)
2. If yes: is it the same JS the reviewed build runs, updated for fixes — or can it add screens and features?
3. Can a server response change what the app *does* (not just what content it shows)? Feature flags that unlock
   unreviewed features count.
4. Is any part of the main experience a remote web app? Who can change it, and how often does it change?
5. Was the project generated by an app builder? Which one, and which of its runtime services are still enabled?
6. Is there any `eval`, `new Function`, `evaluateScript`, dynamic class or assembly loading in the code or in a
   dependency you control?

## Verdicts

| Situation | Risk | Recommendation |
|---|---|---|
| OTA used for bug fixes to reviewed features only | Low | Keep; document the policy in the team's release notes |
| OTA used to ship new features or screens | High | Ship features through review; restrict OTA to fixes |
| Server-driven UI that can add new functionality | High | Limit the server to content; features in the binary |
| Main experience is a hosted web app | High (also 4.2) | Native value of its own, or do not ship as an app |
| `eval` of strings fetched from a server | High | Remove |
| `eval` of bundled, static strings | Low | Prefer removing; explain if asked |
