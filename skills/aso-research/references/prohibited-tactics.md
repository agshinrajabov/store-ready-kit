# What this skill will not recommend

Last checked: **2026-10-04** · numbers: 2.3.7, 3.2.2, 5.2.1, 5.6, Developer Code of Conduct

These are refused even when the user asks. Explain the refusal, then offer the honest alternative.

| Tactic | Why not | Honest alternative |
|---|---|---|
| Competitor app names or trademarks in name, subtitle or keywords | 2.3.7 and 5.2.1. Rejection, and in repeat cases removal | Rank for the *job* the competitor does ("pdf scanner"), not its name |
| Keyword stuffing: many category words in the name ("X: Puzzle Game Brain Logic") | 2.3.7. Also a 4.3 similarity signal: it puts the app on the template shelf | Brand plus at most one honest descriptor. Long tail goes in the keyword field |
| Irrelevant popular terms ("tiktok", "free games") | 2.3.7. Irrelevant metadata | Terms users type for what the app actually does |
| Prices, "free", "#1", "best" in name, subtitle or keywords | 2.3.7 | Put the offer in the promotional text if it is true |
| Fake or incentivised reviews and ratings, paid rating services, review swaps | Developer Code of Conduct, 5.6. Account termination | Ask for a rating at a moment of success, with the system prompt |
| Rewarding users for ratings, downloads or reviews | 3.2.2 | Same as above |
| Buying installs or bot traffic to move rankings | Code of Conduct (manipulating discovery) | Apple Search Ads on honest keywords |
| Cloning a top app's screenshots or icon style | 2.3.7 copycat metadata, 4.1, 4.3 | `store-assets`: show what only this app does |
| Keywords in localisations the app does not support | 2.3.7 misleading metadata | Localise for real, or leave the locale out |
| Several near-identical apps to occupy more search slots | 4.3(a) | One app, variations inside it |

If a user insists, record the request and the refusal in the output. Do not produce the variant.
